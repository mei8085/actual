## 三、完整状态流转图

```
                    ┌──────────────────┐
                    │   Uncleared      │
                    │  未结算           │
                    │ cleared=false    │
                    │ reconciled=false │
                    └────────┬─────────┘
                             │
                  点击状态列 / 批量操作
                  快捷键 L / 银行导入
                             ▼
                    ┌──────────────────┐
        ┌──────────▶│     Cleared      │◀──────────┐
        │           │    已结算         │           │
        │           │ cleared=true     │           │
        │           │ reconciled=false │           │
        │           └────────┬─────────┘           │
        │                    │                     │
        │          对账模式完成 "Lock"             │
        │          批量查询: cleared=true,         │
        │          reconciled=false 的全部交易     │
        │                    │                     │
  点击状态列解锁:                              点击状态列 / 批量操作
  弹窗确认 → reconciled=false
        │                    ▼                     │
        │           ┌──────────────────┐          │
        └───────────│   Reconciled     │──────────┘
                    │   已对账          │
                    │ cleared=true     │
                    │ reconciled=true  │
                    └──────────────────┘

  ── 对账模式差额不为 0 时 ─────────────────────────────────────
  │ 点击 "Create reconciliation transaction"             │
  │    ↓                                                   │
  │ 新建调节交易: cleared=true, reconciled=false           │
  │ notes = "Reconciliation balance adjustment"            │
  │ amount = 银行余额 - 已结算余额                          │
  │    ↓                                                   │
  │ → 作为 Cleared 状态参与对账（下次 Lock 时被一并锁定）   │
  ─────────────────────────────────────────────────────────

  特殊约束: Reconciled 状态下点击 cleared 不会只切换 cleared，
  而是触发解锁流程 → 先将 reconciled 设为 false

  拦截体系（所有影响对账余额的操作）:
  ┌─────────────────────────────────────────────────────┐
  │ 单行/批量: 编辑 amount/payee/account/date             │
  │ 单行/批量: 删除                                       │
  │ 批量: 组合转账关系                                    │
  │    ↓ 两级检测                                         │
  │  Step 1: 选中交易自身 reconciled=true?                │
  │    ├─ 是 → 弹 confirm-transaction-edit                │
  │    └─ 否 → Step 2: 关联转账对方 reconciled=true?      │
  │           ├─ 是 → 弹 *Transfer 后缀确认               │
  │           └─ 否 → 直接放行                             │
  └─────────────────────────────────────────────────────┘
```

### 4.3 路径 C：已对账 → 已结算（`reconciled=false`，解锁）

- **位置**：[TransactionsTable.tsx#L1071-L1086](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/transactions/TransactionsTable.tsx#L1071-L1086)

### 4.4 路径 D：对账差额 → 创建调节交易（附带状态设置）

#### 入口：对账模式差额不为零时「Create reconciliation transaction」

- **位置**：
  - 触发按钮：[Reconcile.tsx#L113-L117](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/accounts/Reconcile.tsx#L113-L117)
  - 创建逻辑：[Account.tsx#L1038-L1070](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/accounts/Account.tsx#L1038-L1070)
- **触发场景**：对账模式下，「已结算余额」与「输入的银行余额」差值不为 0 时，用户选择「Create reconciliation transaction」创建调节交易以消除差额
- **核心逻辑**：

  ```typescript
  onCreateReconciliationTransaction = async (diff: number) => {
    const reconciliationTransactions = realizeTempTransactions([
      {
        id: 'temp',
        account: this.props.accountId!,
        cleared: true, // ⚠️ 调节交易默认已结算
        reconciled: false, // ⚠️ 调节交易默认未对账
        amount: diff, // 差额为正记收入，负记支出
        date: currentDay(),
        notes: t('Reconciliation balance adjustment'),
      },
    ]);

    // 1. 先进行规则匹配（可能被分类到某个账户）
    const ruledTransactions = await Promise.all(
      reconciliationTransactions.map(transaction =>
        send('rules-run', { transaction }),
      ),
    );

    // 2. 落库（added）
    await send('transactions-batch-update', {
      added: ruledTransactions.filter(trans => !trans.tombstone),
      deleted: ruledTransactions.filter(trans => trans.tombstone),
    });
  };
  ```

- **状态语义**：
  - `cleared=true`：调节交易默认视为已被银行清算（因为它是用来平账的）
  - `reconciled=false`：调节交易需要和其他交易一起，在下一次对账 Lock 时一并锁定；或用户可单独点击状态列手动锁定
  - `notes='Reconciliation balance adjustment'`：标记为对账调节交易，便于后续审计

- **影响范围**：
  - 创建一条新交易，金额等于差额（diff），方向由差额正负决定
  - 若规则引擎命中（如自动分类到某个费用/收入账户），交易的 category / transfer_id 等字段会被修改
  - 创建后立即在列表中显示，并参与当前对账会话的已结算余额计算

## 五、已对账（reconciled）的二次确认拦截体系

所有对 `reconciled=true` 交易的破坏性操作（编辑关键字段、删除）、以及对其关联转账对方的破坏性操作，都会经过统一的二次确认拦截。

### 5.1 确认弹窗：ConfirmTransactionEditModal

弹窗本体：[ConfirmTransactionEditModal.tsx](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/modals/ConfirmTransactionEditModal.tsx)

弹窗根据 `confirmReason` 参数展示不同的提示文案：

| confirmReason                       | 触发场景                                              | 提示内容                                                             |
| ----------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------- |
| `editReconciled`                    | 单行编辑已对账交易的关键字段（金额/账户/收款人/日期） | 「保存对已对账交易的更改可能导致对账余额失衡」                       |
| `unlockReconciled`                  | 点击已对账交易的状态列（解锁）                        | 「解锁后，对金额、账户、收款人等的修改将不再被警告」                 |
| `batchEditWithReconciled`           | 批量编辑包含已对账交易                                | 「编辑已对账交易可能导致对账余额失衡」                               |
| `batchEditWithReconciledTransfer`   | 批量编辑的交易中存在**关联转账对方是已对账状态**      | 「该转账在另一个账户有关联的已对账交易，编辑可能导致该账户对账失衡」 |
| `batchDeleteWithReconciled`         | 批量删除包含已对账交易                                | 「删除已对账交易可能导致对账余额失衡」                               |
| `batchDeleteWithReconciledTransfer` | 批量删除的交易中存在**关联转账对方是已对账状态**      | 「该转账在另一个账户有关联的已对账交易，删除可能导致该账户对账失衡」 |
| `deleteReconciled`                  | 单行删除已对账交易                                    | 「删除已对账交易可能导致对账余额失衡」                               |

### 5.2 拦截检测函数：checkForReconciledTransactions

统一入口：[useTransactionBatchActions.ts#L451-L518](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/hooks/useTransactionBatchActions.ts#L451-L518)

该函数采用 **两级检测**：

```
Step 1: 检查"选中交易本身"是否有 reconciled=true
  ├─ 是 → 弹 confirm-transaction-edit（reason: batchEditWithReconciled / batchDeleteWithReconciled）
  └─ 否 → 进入 Step 2

Step 2: 检查"选中交易的关联转账对方"（transfer_id）是否有 reconciled=true
  ├─ 是 → 弹 confirm-transaction-edit（reason: *Transfer 后缀变体）
  └─ 否 → 直接放行，执行后续操作（无弹窗）
```

两级检测的核心代码：

```typescript
const checkForReconciledTransactions = async (
  ids,
  confirmReason,
  onConfirm,
) => {
  // Step 1: 检查选中的交易自身是否已对账
  const { data } = await aqlQuery(
    q('transactions')
      .filter({ id: { $oneof: ids }, reconciled: true })
      .select('*')
      .options({ splits: 'grouped' }),
  );
  const transactions = ungroupTransactions(data as TransactionEntity[]);

  if (transactions.length > 0) {
    // 自身已对账 → 弹窗
    dispatch(
      pushModal({
        modal: {
          name: 'confirm-transaction-edit',
          options: { confirmReason, onConfirm },
        },
      }),
    );
    return;
  }

  // Step 2: 检查关联转账对方是否已对账
  const { data: selectedData } = await aqlQuery(
    q('transactions')
      .filter({ id: { $oneof: ids } })
      .select(['transfer_id']),
  );

  const transferIds = (selectedData as TransactionEntity[])
    .map(t => t.transfer_id)
    .filter((id): id is string => id != null);

  if (transferIds.length > 0) {
    const { data: reconciledTransfers } = await aqlQuery(
      q('transactions')
        .filter({ id: { $oneof: transferIds }, reconciled: true })
        .select('*'),
    );

    if ((reconciledTransfers as TransactionEntity[]).length > 0) {
      // 对方已对账 → 弹窗（使用 *Transfer 后缀的 reason）
      dispatch(
        pushModal({
          modal: {
            name: 'confirm-transaction-edit',
            options: {
              confirmReason: transferReasonMap[confirmReason], // e.g. batchDeleteWithReconciledTransfer
              onConfirm,
            },
          },
        }),
      );
      return;
    }
  }

  // 两级都未命中 → 直接执行
  onConfirm(ids);
};
```

### 7.2 父/子（拆分）交易联动的四个传播路径

#### 7.2.1 新建子交易时的状态继承
位置：[transactions.ts#L33-L59](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/loot-core/src/shared/transactions.ts#L33-L59)

`makeChild(parent, data)` 创建新子交易时，从父交易完整继承以下字段：

```typescript
return {
  amount: 0,
  ...data,
  category: 'category' in data ? data.category : parent.category,
  payee: 'payee' in data ? data.payee : parent.payee,
  id: 'id' in data ? data.id : prefix + uuidv4(),
  account: parent.account,                    // 必传
  date: parent.date,                          // 必传
  cleared: parent.cleared != null ? parent.cleared : null,    // ← 状态继承
  reconciled: parent.reconciled != null ? parent.reconciled : null,  // ← 状态继承
  starting_balance_flag: parent.starting_balance_flag != null ? parent.starting_balance_flag : null,

```

- `cleared` / `reconciled` 直接从父交易复制，子交易与父交易状态完全一致
- `category` / `payee` 只有在子交易未单独设置时才继承父交易的值

#### 7.2.2 父交易更新时子交易状态联动（updateTransaction）
位置：[transactions.ts#L259-L297](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/loot-core/src/shared/transactions.ts#L259-L297)

当通过 `updateTransaction` 更新父交易时，会遍历所有子交易并调用 `makeChild(parent, child)` 重建子交易：

```typescript
if (trans.is_parent) {
  const parent = trans.id === transaction.id ? { ...trans, ...transaction } : trans;
  const sub = originalSubtransactions?.map(t => {
    // 如果更新的是父交易本身，子交易的 payee 会同步（如果与旧父相同）
    if (trans.id === transaction.id) {
      const { payee: childPayee, ...rest } = t;
      const newPayee = childPayee === trans.payee ? transaction.payee : childPayee;
      child = { ...rest, ...(newPayee != null ? { payee: newPayee } : {}) };
    } else if (t.id === transaction.id) {
      child = transaction;  // 直接更新子交易
    }
    return makeChild(parent, child);  // ← 所有子交易重新继承父状态
  });

  return recalculateSplit({ ...parent, ...(sub && { subtransactions: sub }) });
}
```

**传播规则**：
- 父交易的 `cleared` / `reconciled` 变更会通过 `makeChild` 同步到**所有子交易**
- 父交易的 `account` / `date` 变更也会同步到所有子交易
- 子交易的 `payee` 只有在与旧父交易 `payee` 相同时才会同步新值
- 子交易的 `category` 不随父交易自动同步（保持各自的分类）

#### 7.2.3 银行同步时父交易状态联动（sync.ts 特殊路径）

| `schedule` | `keep.schedule \|\| drop.schedule` | OR 逻辑 |
| `category` | `keep.category \|\| drop.category` | 仅普通合并；有子交易时强制 `null` |
| `amount` | 保留 keep.amount | 前置条件要求两者 amount 相等 |
| `date` | 保留 keep.date | 由 determineKeepDrop 决定 |
| `imported_id` | 保留 keep.imported_id | 同上 |

#### 7.3.4 子交易迁移（drop 有子交易，keep 没有时）
位置：[merge.ts#L65-L85](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/loot-core/src/server/transactions/merge.ts#L65-L85)

当合并的两条交易中，被丢弃方（drop）有拆分的子交易，但保留方（keep）没有时：

1. **批量更新子交易的 `parent_id`**：将 drop 的所有子交易挂到 keep 下
   ```typescript
   await Promise.all(
     dropSubtransactions.map(sub =>
       db.updateTransaction({ id: sub.id, parent_id: keep.id }),
     ),
   );
   ```

2. **将 keep 升级为父交易**：
   ```typescript
   await db.updateTransaction({
     id: keep.id,
     is_parent: true,
     category: null,  // 父交易不能有自己的分类
     payee: keep.payee || drop.payee,
     notes: keep.notes || drop.notes,
     cleared: keep.cleared || drop.cleared,
     reconciled: keep.reconciled || drop.reconciled,
     schedule: keep.schedule || drop.schedule,
   });
   ```

**子交易状态保持不变**：迁移后的子交易保留自身的 `cleared` / `reconciled` 状态，不会被重新继承（与 `updateTransaction` 路径不同）。

#### 7.3.5 删除被合并交易
位置：[merge.ts#L99-L111](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/loot-core/src/server/transactions/merge.ts#L99-L111)

使用 `sharedDeleteTransaction` 智能处理可能的父子级联删除：

```typescript
const { data: transactionsToDelete } = await aqlQuery(
  q('transactions').filter({ id: drop.id }).select('*').options({ splits: 'grouped' }),
);
const ungroupedTransactions = ungroupTransactions(transactionsToDelete);
if (ungroupedTransactions.length > 0) {
  const { diff } = sharedDeleteTransaction(ungroupedTransactions, drop.id);
  await batchUpdateTransactions(diff);  // 统一走 CRDT 同步
}
```

#### 7.3.6 影响范围
- 合并成功后，`drop` 交易被删除，`keep` 交易保留并合并字段
- 若发生子交易迁移，`drop` 的子交易全部归属于 `keep`
- 所有数据库变更通过 `batchUpdateTransactions` 走 CRDT 同步
- 前端选中状态更新为只选中 `keep.id`
