## 二、状态优先级与视觉呈现

### 2.1 状态显示优先级

UI 渲染时按以下优先级判断显示状态（优先级从高到低）：

```
reconciled = true  →  "reconciled" 状态（锁图标）
    ↓
cleared = true     →  "cleared" 状态（实心对勾图标）
    ↓
两者都为 false     →  "uncleared" 状态（空心圆圈图标，UI 表现为 null）
```

核心代码位于 [TransactionsTable.tsx#L1878-L1886](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/transactions/TransactionsTable.tsx#L1878-L1886)：

```tsx

  isPreview
    ? (previewStatus as StatusTypes)
    : reconciled
      ? 'reconciled'
      : cleared
        ? 'cleared'
        : null
}
```

### 2.2 状态视觉属性表

在 [StatusBadge.tsx#L33-L92](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/schedules/StatusBadge.tsx#L33-L92) 中定义：

## 三、完整状态流转图

```
                    ┌──────────────────┐
                    │   Uncleared      │
                    │  未结算           │
                    │ cleared=false    │
                    │ reconciled=false │
                    └────────┬─────────┘
                             │
                  点击状态列 / 批量操作
                  快捷键 L / 银行导入
                             ▼
                    ┌──────────────────┐
        ┌──────────▶│     Cleared      │◀──────────┐
        │           │    已结算         │           │
        │           │ cleared=true     │           │
        │           │ reconciled=false │           │
        │           └────────┬─────────┘           │
        │                    │                     │
        │          对账模式完成 "Lock"             │
        │          批量查询: cleared=true,         │
        │          reconciled=false 的全部交易     │
  点击状态列解锁:                              点击状态列 / 批量操作
  弹窗确认 → reconciled=false
        │                    │                     │
        │                    ▼                     │
        │           ┌──────────────────┐          │
        └───────────│   Reconciled     │──────────┘
                    │   已对账          │
                    │ cleared=true     │
                    │ reconciled=true  │
                    └──────────────────┘

  特殊约束: Reconciled 状态下点击 cleared 不会只切换 cleared，
  而是触发解锁流程 → 先将 reconciled 设为 false
```

### 4.3 路径 C：已对账 → 已结算（`reconciled=false`，解锁）

#### 入口：点击已对账交易的状态列

- **位置**：[TransactionsTable.tsx#L1071-L1086](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/desktop-client/src/components/transactions/TransactionsTable.tsx#L1071-L1086)
- **触发方式**：在 `reconciled` 状态的交易行上点击状态列（锁图标）
- **流程**：
  1. 不直接切换 `cleared`，而是先弹出确认对话框（`confirmReason: 'unlockReconciled'`）
  2. 用户确认后，执行 `onUpdateAfterConfirm('reconciled', false)`
  3. 结果：`reconciled` 变为 false，`cleared` 仍保持 true → 回到「已结算」状态

```typescript
// Allow un-reconciling (unlocking) transactions
if (name === 'cleared' && transaction.reconciled) {
  dispatch(
    pushModal({
      modal: {
        name: 'confirm-transaction-edit',
        options: {
          onConfirm: () => {
            onUpdateAfterConfirm('reconciled', false); // 只解锁，不动 cleared
          },
          confirmReason: 'unlockReconciled',
        },
      },
    }),
  );
}
```

## 六、数据流转完整链路

### 6.1 调用链总览

```
UI 操作
  ↓
onUpdate / onBatchEdit  (前端)
  ↓
onUpdateAfterConfirm  (确认弹窗处理 + 特殊规则应用)
  ↓
onSave → deserializeTransaction  (Serialized→Entity 转换)
  ↓
updateTransaction (共享函数, 处理父/子交易联动)
  ↓
send('transactions-batch-update', changes)  (IPC/网络调用)
  ↓
handleBatchUpdateTransactions (loot-core server)
  ↓
batchUpdateTransactions  (核心批量处理)
  ↓
db.updateTransaction / db.insertTransaction / db.deleteTransaction
  ↓
同步消息（CRDT）→ 多设备同步
```

### 6.2 父/子（拆分）交易联动

在 [transactions.ts#L47-L48](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/loot-core/src/shared/transactions.ts#L47-L48) 中，新建子交易时继承父交易状态：

```typescript
cleared: parent.cleared != null ? parent.cleared : null,
reconciled: parent.reconciled != null ? parent.reconciled : null,
```

银行对账匹配时，若父交易的 `cleared` 或 `date` 变化，会同步到所有子交易（[sync.ts#L626-L644](file:///d:/fz/0601-1/solo-dogfeeding/code/2-actual/packages/loot-core/src/server/accounts/sync.ts#L626-L644)）。
