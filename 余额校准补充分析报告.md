## 一、首次同步与增量同步起始日期判定

### 1.1 统一规则（精确实现）

**核心规则**：
> **起始日期 = MAX(90天前, 账户最早交易日)**

```typescript
// accounts/sync.ts#L89-L101
async function getAccountSyncStartDate(id) {
  // GoCardless 限制最多获取 90 天数据，作为最早可能限制
  const dates = [monthUtils.subDays(monthUtils.currentDay(), 90)];

  const oldestTransaction = await getAccountOldestTransaction(id);

  if (oldestTransaction) dates.push(oldestTransaction.date);

  // 返回两个日期中较晚的一个（MAX）
  return monthUtils.dayFromDate(
    dateFns.max(dates.map(d => monthUtils.parseDate(d))),
  );
}
```

### 1.2 首次同步 vs 增量同步对比（统一规则）

| 对比项 | 首次同步 (`newAccount = true`) | 增量同步 (`newAccount = false`) |
|--------|-------------------------------|--------------------------------|
| **判定条件** | `oldestTransaction == null` | `oldestTransaction != null` |
| **起始日期计算** | `MAX(90天前, 账户最早交易日)`<br>（新账户无交易记录，dates 数组仅包含 90 天前） | `MAX(90天前, 账户最早交易日)`<br>（取较晚者，受 90 天限制） |
| **起始余额处理** | 创建起始余额交易 | 不创建 |
| **余额更新** | 通过起始交易间接设置 | 直接更新 `balance_current` |
| **GoCardless `includeBalance`** | `true` | `false` |

> **说明**：首次同步与增量同步使用**同一公式**计算起始日期。新账户场景下，由于 `oldestTransaction` 为 `null`，代码中 `dates` 数组仅包含 `[90天前]` 一个元素，因此结果必然是 90 天前。

### 1.3 示例计算

**场景**：当前日期 2024-01-15

| 场景 | 最早交易日期 | 90天前日期 | 同步起始日期 | 说明 |
|------|--------------|------------|--------------|------|
| 新账户 | 无 | 2023-10-17 | **2023-10-17** | MAX(2023-10-17, 无) = 2023-10-17 |
| 交易在 180 天前 | 2023-07-15 | 2023-10-17 | **2023-10-17** | MAX(2023-10-17, 2023-07-15) = 2023-10-17 |
| 交易在 60 天前 | 2023-11-15 | 2023-10-17 | **2023-11-15** | MAX(2023-10-17, 2023-11-15) = 2023-11-15 |
| 交易在 30 天前 | 2023-12-15 | 2023-10-17 | **2023-12-15** | MAX(2023-10-17, 2023-12-15) = 2023-12-15 |

## 二、import 模式入口：start-import 与 batch-budget-start 的职责边界

### 2.1 职责对比

| API | 职责 | 调用时机 | 是否设置 import 模式 |
|-----|------|----------|---------------------|
| `api/start-import` | 启动完整的预算导入流程 | 导入开始时调用一次 | **是**（核心入口） |
| `api/batch-budget-start` | 启动批量操作事务 | 批量写入数据前调用 | **否**（依赖已设置的模式） |

### 2.2 api/start-import（导入模式核心入口）

```typescript
// api.ts#L300-L316
handlers['api/start-import'] = async function ({ budgetName }) {
  // 1. 关闭当前打开的预算
  await handlers['close-budget']();

  // 2. 创建新预算
  await handlers['create-budget']({ budgetName, avoidUpload: true });

  // 3. 清除默认支出分类（为导入做准备）
  db.runQuery('DELETE FROM categories WHERE is_income = 0');
  db.runQuery('DELETE FROM category_groups WHERE is_income = 0');

  // 4. 进入 import 模式 ← 关键：设置同步模式
  setSyncingMode('import');

  // 5. 通知客户端开始导入流程
  connection.send('start-import');
  
  // 6. 设置全局导入标志
  IMPORT_MODE = true;
};
```

**职责范围**：
- 关闭现有预算
- 创建新预算容器
- 清理默认数据
- **设置 import 同步模式**
- 通知 UI 状态变更

### 2.3 api/batch-budget-start（批量操作辅助入口）

```typescript
// api.ts#L129-L150
handlers['api/batch-budget-start'] = async function () {
  if (batchPromise) {
    throw APIError('Cannot start a batch process: batch already started');
  }

  // 根据当前模式选择不同的事务类型
  if (IMPORT_MODE) {
    // 导入模式：直接数据库事务（跳过同步层）
    void db.asyncTransaction(() => {
      return new Promise((resolve, reject) => {
        batchPromise = { resolve, reject };
      });
    });
  } else {
    // 正常模式：通过同步层批量消息
    void batchMessages(() => {
      return new Promise((resolve, reject) => {
        batchPromise = { resolve, reject };
      });
    });
  }
};
```

**职责范围**：
- 创建批量操作的事务上下文
- 根据 `IMPORT_MODE` 标志选择执行路径
- **不负责设置同步模式**（依赖 start-import 已设置）

## 三、import 模式退出路径（含 abort-import 分支）

### 3.1 退出路径总览

| 退出方式 | 触发条件 | 处理逻辑 |
|----------|----------|----------|
| `api/finish-import` | 导入成功完成 | 重新加载预算，恢复正常模式 |
| `api/abort-import` | 导入失败或用户取消 | 删除创建的预算，返回预算列表 |

### 3.2 api/finish-import（正常退出）

```typescript
// api.ts#L318-L339
handlers['api/finish-import'] = async function () {
  checkFileOpen();

  // 1. 标记缓存脏
  sheet.get().markCacheDirty();

  // 2. 重新加载预算 ← 关键：会根据配置设置新的同步模式
  await handlers['load-budget']({ id });

  // 3. 等待电子表格处理完成
  await handlers['get-budget-bounds']();
  await sheet.waitOnSpreadsheet();

  // 4. 尝试上传到云存储
  await cloudStorage.upload().catch(err => {
    logger.warn('cloudStorage.upload failed during finish-import', err);
  });

  // 5. 通知客户端导入完成
  connection.send('finish-import');
  
  // 6. 清除全局导入标志
  IMPORT_MODE = false;
};
```

### 3.3 api/abort-import（异常退出）

```typescript
// api.ts#L341-L351
handlers['api/abort-import'] = async function () {
  if (IMPORT_MODE) {
    checkFileOpen();

    // 1. 获取当前预算 ID
    const { id } = prefs.getPrefs();

    // 2. 关闭当前预算
    await handlers['close-budget']();
    
    // 3. 删除创建的预算（清理临时数据）
    await handlers['delete-budget']({ id });
    
    // 4. 通知客户端显示预算列表
    connection.send('show-budgets');
  }
};
```

**abort-import 特点**：
- 仅在 `IMPORT_MODE = true` 时执行
- 删除整个预算（而非仅回滚事务）
- 不调用 `load-budget`，直接返回预算列表

## 四、import 模式与其他模式的关系

### 4.1 模式检查逻辑（精确实现）

```typescript
// sync/index.ts#L65-L78
export function checkSyncingMode(mode: SyncingMode): boolean {
  switch (mode) {
    case 'enabled':
      return SYNCING_MODE === 'enabled' || SYNCING_MODE === 'offline';
    case 'disabled':
      return SYNCING_MODE === 'disabled' || SYNCING_MODE === 'import';
    case 'offline':
      return SYNCING_MODE === 'offline';
    case 'import':
      return SYNCING_MODE === 'import';
    default:
      throw new Error('checkSyncingMode: invalid mode: ' + mode);
  }
}
```

### 4.2 模式转换规则

| 当前模式 | 可切换到 | 切换触发点 |
|----------|----------|------------|
| `enabled` | `offline`, `disabled`, `import` | 配置变化、`start-import` |
| `offline` | `enabled` | 连接恢复 |
| `disabled` | `enabled`, `import` | 配置变化、`start-import` |
| `import` | `enabled`, `disabled` | `finish-import` → `load-budget` |
| `import` | -（直接退出） | `abort-import` → 删除预算 |

### 4.3 调度影响总结

| 模式 | CRDT 处理 | 全量同步 | 电子表格更新 |
|------|----------|----------|--------------|
| `enabled` | ✅ | ✅ | ✅ |
| `offline` | ✅ | ❌ | ✅ |
| `disabled` | ❌ | ❌ | ✅ |
| `import` | ❌ | ❌ | ❌ |

**场景**：2024-01-15 绑定新账户，银行返回 30 天交易

```

同步起始日期 = MAX(2023-10-17, 2023-06-01) = 2023-10-17 ✓
```
