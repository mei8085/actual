## 一、首次同步起始日期判定逻辑

### 1.1 判定规则（精确实现）

```typescript
// accounts/sync.ts#L89-L101
async function getAccountSyncStartDate(id) {
  // GoCardless 限制最多获取 90 天数据，作为最早可能限制
  const dates = [monthUtils.subDays(monthUtils.currentDay(), 90)];

  const oldestTransaction = await getAccountOldestTransaction(id);

  if (oldestTransaction) dates.push(oldestTransaction.date);

  // 返回两个日期中较晚的一个（MAX）
  return monthUtils.dayFromDate(
    dateFns.max(dates.map(d => monthUtils.parseDate(d))),
  );
}
```

**核心规则**：
> **起始日期 = MAX(90天前, 账户最早交易日)**

| 场景 | 计算结果 | 说明 |
|------|----------|------|
| 新账户（无交易） | 90天前 | 从 90 天前开始同步 |
| 已有交易且最早交易 < 90天前 | 90天前 | 受限于银行 API 限制 |
| 已有交易且最早交易 > 90天前 | 最早交易日期 | 从最近的交易开始增量同步 |

### 1.2 示例计算

**场景**：当前日期 2024-01-15

| 账户状态 | 最早交易日期 | 90天前日期 | 同步起始日期 |
|----------|--------------|------------|--------------|
| 新账户 | 无 | 2023-10-17 | **2023-10-17** |
| 交易在 180 天前 | 2023-07-15 | 2023-10-17 | **2023-10-17** |
| 交易在 60 天前 | 2023-11-15 | 2023-10-17 | **2023-11-15** |
| 交易在 30 天前 | 2023-12-15 | 2023-10-17 | **2023-12-15** |

### 1.3 首次同步 vs 增量同步对比

| 对比项 | 首次同步 (`newAccount = true`) | 增量同步 (`newAccount = false`) |
|--------|-------------------------------|--------------------------------|
| **判定条件** | `oldestTransaction == null` | `oldestTransaction != null` |
| **起始日期计算** | `MAX(90天前, 当前日期)` | `MAX(90天前, 最早交易日期)` |
| **起始余额处理** | 创建起始余额交易 | 不创建 |
| **余额更新** | 通过起始交易间接设置 | 直接更新 `balance_current` |
| **GoCardless `includeBalance`** | `true` | `false` |

## 二、import 模式的进入与退出路径

### 2.1 import 模式定义

`import` 模式是一种**高性能批量导入优化模式**，用于：
- 大量数据导入（如从其他财务软件迁移）
- 测试环境数据初始化
- Demo 预算创建

**核心特点**：跳过 CRDT 同步验证，直接写入数据库。

### 2.5 模式检查逻辑（精确实现）

```typescript
// sync/index.ts#L65-L78
export function checkSyncingMode(mode: SyncingMode): boolean {
  switch (mode) {
    case 'enabled':
      return SYNCING_MODE === 'enabled' || SYNCING_MODE === 'offline';
    case 'disabled':
      return SYNCING_MODE === 'disabled' || SYNCING_MODE === 'import';
    case 'offline':
      return SYNCING_MODE === 'offline';
    case 'import':
      return SYNCING_MODE === 'import';
    default:
      throw new Error('checkSyncingMode: invalid mode: ' + mode);
  }
}
```

**语义解读**：

| 检查模式 | 返回 true 的实际模式 | 含义 |
|----------|--------------------|------|
| `checkSyncingMode('enabled')` | `enabled` 或 `offline` | 允许本地变更（可同步或离线） |
| `checkSyncingMode('disabled')` | `disabled` 或 `import` | 禁止服务器同步 |
| `checkSyncingMode('offline')` | `offline` | 严格离线模式 |
| `checkSyncingMode('import')` | `import` | 导入优化模式 |

## 三、import 模式对调度的影响

### 3.1 消息处理路径差异

```typescript
// sync/index.ts#L261-L265
export const applyMessages = sequential(async (messages: Message[]) => {
  // import 模式：快速路径
  if (checkSyncingMode('import')) {
    applyMessagesForImport(messages);  // 直接写入数据库
    return undefined;  // 跳过后续 CRDT 处理
  } 
  // enabled 模式：完整路径
  else if (checkSyncingMode('enabled')) {
    messages = await compareMessages(messages);  // CRDT 验证
  }
  // ... CRDT 处理、Merkle 更新、预算变更触发
});
```

### 3.2 applyMessagesForImport 实现

```typescript
// sync/index.ts#L231-L250
function applyMessagesForImport(messages: Message[]): void {
  db.transaction(() => {
    for (let i = 0; i < messages.length; i++) {
      const msg = messages[i];
      const { dataset } = msg;

      if (!msg.old) {
        try {
          apply(msg);        // 尝试插入
        } catch {
          apply(msg, true);  // 失败则更新
        }

        if (dataset === 'prefs') {
          throw new Error('Cannot set prefs while importing');
        }
      }
    }
  });
}
```

**关键差异**：

| 处理阶段 | import 模式 | enabled/offline 模式 |
|----------|------------|---------------------|
| CRDT 消息比较 | 跳过 | 执行 `compareMessages()` |
| Merkle Trie 更新 | 跳过 | 执行 `merkle.insert()` |
| 同步监听器触发 | 跳过 | 执行 `_syncListeners` |
| 预算变更触发 | 跳过 | 执行 `triggerBudgetChanges()` |
| 电子表格更新 | 跳过 | 执行 `triggerDatabaseChanges()` |

### 3.3 全量同步调度影响

```typescript
// sync/index.ts#L550-L567
export function scheduleFullSync(): Promise<...> {
  clearFullSyncTimeout();

  // import 模式下 checkSyncingMode('enabled') 返回 false
  // 因此不会触发全量同步
  if (checkSyncingMode('enabled') && !checkSyncingMode('offline')) {
    if (process.env.NODE_ENV === 'test') {
      return fullSync().then(res => { ... });
    } else {
      syncTimeout = setTimeout(fullSync, FULL_SYNC_DELAY);
    }
  }
}
```

**影响总结**：
- `import` 模式下 `scheduleFullSync()` 无任何操作
- 批量导入期间不会触发与服务器的同步
- 所有变更在 `finish-import` 后通过 `load-budget` 统一处理

## 五、模式切换总结

### 5.1 模式关系矩阵

| 当前模式 | 可切换到 | 切换触发点 |
|----------|----------|------------|
| `enabled` | `offline`, `disabled`, `import` | 配置变化、导入开始 |
| `offline` | `enabled` | 连接恢复 |
| `disabled` | `enabled`, `import` | 配置变化、导入开始 |
| `import` | `enabled`, `disabled` | `finish-import` → `load-budget` |

### 5.2 调度影响总结

| 模式 | CRDT 处理 | 全量同步 | 电子表格更新 |
|------|----------|----------|--------------|
| `enabled` | ✅ | ✅ | ✅ |
| `offline` | ✅ | ❌ | ✅ |
| `disabled` | ❌ | ❌ | ✅ |
| `import` | ❌ | ❌ | ❌ |

### 5.3 设计意图

**import 模式的设计目的**：
1. **性能优化**：批量导入大量数据时跳过 CRDT 开销
2. **原子性保证**：通过 `db.transaction()` 保证导入的原子性
3. **避免冲突**：导入期间不与服务器同步，避免版本冲突
4. **简化流程**：导入完成后通过 `load-budget` 统一恢复状态
