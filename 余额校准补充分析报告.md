# Actual Budget 余额校准补充分析报告

## 一、本地交易与导入记录的对齐机制

### 1.1 首次同步 vs 增量同步判定

系统通过查询账户是否存在交易来判定同步类型：

```typescript
// accounts/sync.ts#L1113-L1114
const oldestTransaction = await getAccountOldestTransaction(id);
const newAccount = oldestTransaction == null;
```

**判定逻辑**：
- 调用 [getAccountOldestTransaction](file:///d:/fz/0508-1/solo-dogfeeding/code/120-actual/packages/loot-core/src/server/accounts/sync.ts#L74-L87) 查询账户最早的交易
- 查询条件：`account = id AND date <= currentDay()`
- 返回 `null` 表示账户无交易 → **首次同步**
- 返回交易记录 → **增量同步**

### 1.2 校准触发条件对比

| 条件 | 首次同步 (`newAccount = true`) | 增量同步 (`newAccount = false`) |
|------|-------------------------------|--------------------------------|
| **触发时机** | 账户刚绑定银行，无任何交易记录 | 账户已有交易，定期或手动同步 |
| **起始日期** | `max(90天前, 当前日期)` | `max(90天前, 最早交易日期)` |
| **起始余额** | 计算历史余额并创建起始交易 | 不创建起始交易 |
| **余额更新** | 通过起始交易设置 | 直接更新 `balance_current` 字段 |
| **GoCardless 特殊处理** | `includeBalance = true` 获取余额 | `includeBalance = false` 仅获取交易 |

### 1.4 差异来源类型

| 差异类型 | 判定条件 | 处理方式 |
|----------|----------|----------|
| **新交易** | `match = null && !trans.tombstone` | 创建新交易记录 |
| **字段变更** | `match != null && hasFieldsChanged()` | 合并字段，本地优先 |
| **已调节交易** | `match.reconciled = true` | 跳过，不更新 |
| **已删除交易** | `trans.tombstone = true` | 仅预览，不恢复 |
| **重复交易** | `match != null && !hasFieldsChanged()` | 标记为 `ignored: true` |

### 1.5 字段变更检测

使用 [hasFieldsChanged](file:///d:/fz/0508-1/solo-dogfeeding/code/120-actual/packages/loot-core/src/shared/util.ts#L32-L46) 函数检测是否需要更新：

```typescript
// shared/util.ts#L32-L46
export function hasFieldsChanged<T extends object>(
  obj1: T,
  obj2: T,
  fields: Array<keyof T>,
) {
  let changed = false;
  for (let i = 0; i < fields.length; i++) {
    const field = fields[i];
    if (obj1[field] !== obj2[field]) {
      changed = true;
      break;
    }
  }
  return changed;
}
```

**检测字段**：`imported_id`, `payee`, `category`, `imported_payee`, `notes`, `cleared`, `raw_synced_data`

### 2.4 scheduleFullSync 实现细节

```typescript
// sync/index.ts#L550-L567
const FULL_SYNC_DELAY = 1000;
let syncTimeout = null;

export function scheduleFullSync(): Promise<...> {
  clearFullSyncTimeout();

  if (checkSyncingMode('enabled') && !checkSyncingMode('offline')) {
    if (process.env.NODE_ENV === 'test') {
      // 测试环境：立即执行
      return fullSync().then(res => {
        if (isError(res)) throw res.error;
        return res;
      });
    } else {
      // 生产环境：延迟 1 秒执行
      syncTimeout = setTimeout(fullSync, FULL_SYNC_DELAY);
    }
  }
}
```

**关键点**：
- 延迟 1 秒是为了合并多个快速变更
- `offline` 模式下不触发服务器同步
- 测试环境立即执行以避免异步问题

### 4.2 同步起始日期计算

```typescript
// accounts/sync.ts#L89-L101
async function getAccountSyncStartDate(id) {
  // GoCardless 限制最多获取 90 天数据
  const dates = [monthUtils.subDays(monthUtils.currentDay(), 90)];

  const oldestTransaction = await getAccountOldestTransaction(id);

  if (oldestTransaction) dates.push(oldestTransaction.date);

  return monthUtils.dayFromDate(
    dateFns.max(dates.map(d => monthUtils.parseDate(d))),
  );
}
```

- 新账户：90 天前
- 已有交易账户：max(90 天前, 最早交易日期)

## 五、总结

### 5.1 对齐机制核心要点

1. **同步类型判定**：通过 `oldestTransaction == null` 区分首次/增量同步
2. **差异来源**：三级匹配策略精确定位新交易、字段变更、已调节交易
3. **字段合并**：本地值优先，仅更新缺失或空值字段
4. **余额一致性**：增量同步直接更新，首次同步通过起始交易设置

### 5.2 同步调度核心要点

1. **模式切换**：由预算加载、服务器配置、环境决定
2. **批处理机制**：`batchMessages` 确保原子性，延迟合并变更
3. **全量同步**：1 秒延迟后执行，与服务器交换 CRDT 消息
4. **import 模式**：快速路径，跳过 CRDT 验证以提升批量导入性能
