# Actual Budget 桥接层分析报告

## 1. 概述

Actual Budget 采用分层架构设计，桌面端（React UI）与核心逻辑（业务逻辑、数据存储）之间通过**桥接层（Bridge Layer）**进行通信。该桥接层承担着请求序列化、权限边界控制和异步响应回调的关键职责，确保前后端分离架构下的数据一致性和操作安全性。

### 3.2 请求流程

#### 客户端发送请求 (`index.electron.ts`)

```typescript
export const send: T.Send = function (name, args, { catchErrors = false } = {}) {
  return new Promise((resolve, reject) => {
    const id = uuidv4();  // 生成唯一请求ID
    replyHandlers.set(id, { resolve, reject });  // 注册回调

    if (socketClient) {
      socketClient.emit('message', {
        id,
        name,           // 方法名，如 'transaction-add'
        args,           // 参数
        undoTag: undo.snapshot(),  // 撤销快照
        catchErrors: !!catchErrors,
      });
    } else {
      messageQueue.push({ /* ... */ });  // 未连接时入队
    }
  });
};
```

#### 服务端接收并处理 (`index.ts`)

```typescript
serverChannel.addEventListener('message', e => {
  const { id, name, args, undoTag, catchErrors } = msg;

  if (handlers[name]) {
    runHandler(handlers[name], args, { undoTag, name }).then(
      result => {
        serverChannel.postMessage({
          type: 'reply',
          id,
          result: catchErrors ? { data: result, error: null } : result,
          mutated: isMutating(handlers[name]),
          undoTag,
        });
      },
      nativeError => {
        const error = coerceError(nativeError);
        // 根据 catchErrors 决定回复格式
        serverChannel.postMessage({ type: 'error' | 'reply', id, error });
      }
    );
  }
});
```

### 3.3 权限边界控制

交易服务通过以下机制实现权限边界：

1. **Mutator 装饰器**：
   - 使用 `mutator()` 装饰器标记修改操作
   - `isMutating(handler)` 检测方法是否会修改数据
   - 只有标记为 mutator 的方法才能执行数据变更

2. **Undo 机制**：
   - 每个请求携带 `undoTag`（撤销快照）
   - 操作失败或需要撤销时可回滚到之前状态
   - 非变异操作执行后自动清理 undo 快照

3. **输入验证**：
   - `moveTransaction` 中验证交易存在性和账户匹配
   - 防止跨账户非法操作

```typescript
// Map -> JSON 字符串
export const mappingsToString = (mapping: Mappings): string =>
  JSON.stringify(
    Object.fromEntries(
      [...mapping.entries()].map(([key, value]) => [
        key,
        Object.fromEntries(value),
      ]),
    ),
  );

// JSON 字符串 -> Map
export const mappingsFromString = (str: string): Mappings => {
  try {
    const parsed = JSON.parse(str);
    return new Map(
      Object.entries(parsed).map(([key, value]) => [
        key,
        new Map(Object.entries(value as object)),
      ]),
    );
  } catch (e) {
    throw new Error(`Failed to parse mapping: ${String(e)}`);
  }
};
```

## 6. 核心桥接机制详解

### 6.1 请求序列化流程

```
客户端组件
    ↓
调用 send('method-name', params)
    ↓
生成唯一请求 ID (UUID)
    ↓
注册 Promise 回调到 replyHandlers Map
    ↓
构造消息体: { id, name, args, undoTag, catchErrors }
    ↓
发送到 IPC / SharedWorker
    ↓
        服务端接收
        ↓
    查找 handlers[name]
        ↓
    执行业务逻辑
        ↓
    构造响应: { type: 'reply', id, result, mutated, undoTag }
        ↓
客户端接收
    ↓
通过 id 查找 replyHandlers 中的回调
    ↓
resolve 或 reject Promise
    ↓
清理回调注册
```

### 6.2 异步响应回调路径

#### 客户端回调管理 (`index.electron.ts`)

```typescript
const replyHandlers = new Map();  // 存储待处理请求的回调

client.on('message', data => {
  const msg = data;

  if (msg.type === 'error') {
    const handler = replyHandlers.get(msg.id);
    if (handler) {
      replyHandlers.delete(msg.id);
      handler.reject(msg.error);  // 拒绝 Promise
    }
  } else if (msg.type === 'reply') {
    const handler = replyHandlers.get(msg.id);
    if (handler) {
      replyHandlers.delete(msg.id);

      if (!msg.mutated) {
        undo.gc(msg.undoTag);  // 非变异操作，清理撤销快照
      }

      handler.resolve(msg.result);  // 解决 Promise
    }
  }
});
```

#### 服务端推送事件 (Server Push)

```typescript
// 服务端发送推送
export const send: T.Send = function (name, args) {
  const { __globalServerChannel } = getGlobalObject();
  if (__globalServerChannel) {
    __globalServerChannel.postMessage({
      type: 'push',
      name,
      args,
    });
  }
};

// 客户端监听推送
const listeners = new Map();

client.on('message', data => {
  if (msg.type === 'push') {
    const { name, args } = msg;
    const listens = listeners.get(name);
    if (listens) {
      for (let i = 0; i < listens.length; i++) {
        const stop = listens[i](args);  // 调用所有监听器
        if (stop === true) break;
      }
    }
  }
});

// 监听 API
export const listen: T.Listen = function (name, cb) {
  if (!listeners.get(name)) {
    listeners.set(name, []);
  }
  listeners.get(name).push(cb);

  return () => {
    // 返回取消监听函数
  };
};
```

### 6.3 权限边界控制机制

#### 1. 方法可见性与注册

```typescript
// app.ts - 只有通过 app.method 注册的方法才可被调用
class App<Handlers> {
  handlers: Handlers;

  method<Name extends string & keyof Handlers>(
    name: Name,
    func: Handlers[Name],
  ) {
    if (this.handlers[name] != null) {
      throw new Error('Conflicting method name: ' + name);
    }
    this.handlers[name] = func;
  }
}

// 服务端连接层 - 只执行已注册的方法
if (handlers[name]) {
  runHandler(handlers[name], args, { undoTag, name });
} else {
  logger.error('Unknown server method: ' + name);
  // 返回未知方法错误
}
```

#### 2. 变异操作标记 (Mutator)

```typescript
// 标记为 mutator 的方法可修改数据
app.method('transactions-batch-update', mutator(undoable(handleBatchUpdateTransactions)));
app.method('transaction-add', mutator(addTransaction));
app.method('transaction-delete', mutator(deleteTransaction));

// 检测方法是否为变异操作
function isMutating(handler) {
  return handler && handler.__mutator === true;
}
```

#### 3. 错误捕获与隔离

```typescript
export const send: T.Send = function (name, args, { catchErrors = false } = {}) {
  // catchErrors 参数控制是否捕获错误并在结果中返回
  // true:  { data, error } 格式，Promise 永远 resolve
  // false: 错误时 reject Promise
};

// 服务端根据 catchErrors 构造不同响应
if (catchErrors) {
  serverChannel.postMessage({
    type: 'reply',
    id,
    result: { error, data: null },

} else {
  serverChannel.postMessage({ type: 'error', id, error });
}
```

## 7. 桥接层特性总结

### 7.1 请求序列化特性

| 特性 | 实现方式 | 说明 |
|------|----------|------|
| **唯一请求标识** | UUID v4 | 每个请求独立 ID，用于回调匹配 |
| **结构化消息** | `{ id, name, args, undoTag, catchErrors }` | 统一消息格式 |
| **离线队列** | `messageQueue` | 连接未就绪时暂存请求 |
| **类型安全** | TypeScript 泛型 `Handlers` | 编译时方法名和参数类型检查 |
| **二进制支持** | Buffer 序列化/反序列化 | 处理大型数据导出 |

### 7.2 权限边界特性

| 特性 | 实现方式 | 说明 |
|------|----------|------|
| **方法白名单** | `handlers` Map | 只有注册的方法可调用 |
| **变异标记** | `mutator()` 装饰器 | 区分只读和修改操作 |
| **撤销机制** | `undoTag` | 支持操作回滚 |
| **错误隔离** | `catchErrors` | 控制错误传播方式 |
| **文件沙箱** | `fs` 模块封装 | 限制文件访问范围 |
| **输入验证** | 业务逻辑内验证 | 防止非法参数 |

### 7.3 异步响应特性

| 特性 | 实现方式 | 说明 |
|------|----------|------|
| **Promise 回调** | `replyHandlers` Map | 请求-响应匹配 |
| **服务端推送** | `listen()` API | 主动事件通知 |
| **多标签协调** | SharedWorker Leader/Follower | 单一后端实例，多标签共享 |
| **Undo GC** | 非变异操作清理 | 内存优化 |

## 9. 结论

Actual Budget 的桥接层设计体现了以下架构优势：

1. **清晰的分层边界**：UI 层与核心逻辑完全分离，通过统一的消息接口通信
2. **强大的并发支持**：SharedWorker 实现多标签页共享单一后端实例
3. **完善的错误处理**：分层错误捕获、隔离和传播机制
4. **类型安全保障**：TypeScript 泛型确保方法调用的类型正确性
5. **可扩展的设计**：通过 `App` 类组合多个服务模块，支持功能扩展

该桥接层成功解决了桌面应用中前后端分离、多标签并发、数据一致性和操作安全性等核心问题，为 Actual Budget 提供了稳定可靠的通信基础。
